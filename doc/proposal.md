## 2. 技术入门说明(面向不懂 FastAPI/Vue3 的用户)

本章用通俗语言解释本项目涉及的新技术,便于理解后续需求与结构。

### 2.1 FastAPI 是什么

FastAPI 是一个 **Python 的 Web 后端框架**。后端 = 在"幕后"干活的服务:它接收浏览器发来的请求(比如"请识别这张图片"),调用 PyTorch 模型完成推理,再把结果(JSON 数据)返回给浏览器。本项目后端的核心代码仍是 Python + PyTorch,与 `model_train.py` 同源;FastAPI 只是给模型"包了一层网页接口"。它的两个附带好处:

- 启动后自动生成交互式接口文档页面 `http://127.0.0.1:8000/docs`,可以直接在网页上试调用每个接口;
- 自带数据校验,能优雅地返回中文错误提示而不是崩溃。

### 2.2 Vue3 / Vite / Element Plus 是什么

- **Vue3**:前端框架。前端 = 浏览器里"看得见、可点击"的界面。Vue3 用 JavaScript 编写,负责页面的布局、上传控件、进度条、表格等一切界面逻辑。
- **Vite**:Vue3 官方推荐的开发服务器/构建工具。开发时它在本机开一个端口(5173)提供网页,并支持修改代码后页面自动刷新(热更新)。
- **Element Plus**:Vue3 生态最常用的**中文组件库**,提供现成的按钮、上传控件、表格、进度条、弹窗提示等,本项目直接选用它,界面专业且开发效率高。

### 2.3 前后端如何配合(数据流动)

```
浏览器(Edge)
  │  打开 http://localhost:5173(Vite 提供的页面)
  │  用户上传图片、点击"开始识别"
  ▼
Vue3 前端(5173)
  │  把图片通过 HTTP 请求发给后端接口 POST http://127.0.0.1:8000/api/classify
  ▼
FastAPI 后端(8000)
  │  预处理图片 → ResNet 推理 → softmax 得猫/狗概率
  │  结果写入 SQLite 历史记录 → 返回 JSON {预测类别、猫概率、狗概率}
  ▼
Vue3 前端(5173)
  │  把 JSON 渲染成界面:类别文字 + 猫/狗概率对比进度条
  ▼
用户看到结果
```

### 2.4 为什么是两个服务(两个端口)

后端跑 Python(模型),前端跑 Node.js(界面),两者技术栈不同、互不干扰:后端负责"算",前端负责"看"。开发期间前端通过 Vite 的代理设置(`/api` 转发到 8000 端口)访问后端,浏览器不会遇到跨域问题。对用户来说只需双击一次"启动.bat",两个服务会先后自动启动,随后浏览器自动打开页面。

## 3. 项目目标与范围

### 3.1 项目目标

交付一个可在本机一键启动的**网页版猫狗分类软件 v1.0**:

- 单张识别:上传一张图片,得到"猫/狗"类别及猫/狗概率对比进度条;
- 批量识别:一次提交多张图片(支持多选文件、直接选择文件夹两种方式),逐张识别并汇总,生成 CSV;
- 历史记录:每次识别自动存入 SQLite,可查看分页列表、删除单条/清空、导出 CSV。

### 3.2 本期范围(v1)

1. 前端 Vue3 + Vite + Element Plus,页面分三个页签:**单张识别、批量识别、历史记录**,界面与提示均为简体中文。
2. 后端 FastAPI + Uvicorn,启动时固定加载工程根目录 `best_model_opt20.pth` 一次并常驻内存,界面无需选择权重。
3. 单张识别输出:类别(猫/狗)+ 猫/狗概率对比进度条 + 置信度百分比。
4. 批量识别两种图片提交方式:① 多选图片文件;② 直接选择文件夹(浏览器递归收集其中图片后上传,后端不扫描本机路径)。
5. 批量结果:页面表格(文件名/预测类别/置信度/备注)+ 汇总统计(总数、成功、失败、猫、狗)+ CSV 下载,CSV 自动保存到 `result/`。
6. 历史记录:单张与批量的每张识别均自动写入 SQLite;历史页支持分页列表(缩略图 + 文件名 + 结果 + 置信度 + 时间)、删除单条、清空全部、导出 CSV。
7. 一键启动脚本 `启动.bat`:自动启动后端与前端并打开浏览器。
8. 仅本机使用(浏览器访问 `http://localhost:5173`),不对外提供访问。

### 3.3 非本期范围(明确不做)

- 用户登录/注册、多用户体系。
- 摄像头实时识别。
- 训练、测试功能的界面入口(不改变现有训练/测试脚本)。
- 界面内选择/切换模型或权重。
- 对非猫狗图片的拒识(见第 12 章风险)。
- 部署到服务器、局域网或公网访问。

## 4. 用户与使用场景

- **用户画像**:本人(自用学习,不熟悉 FastAPI/Vue3,希望借本项目学习前后端分离开发)。
- **核心场景**:双击 `启动.bat` → 浏览器自动打开页面 → 上传一张或一批猫狗图片 → 查看识别结果与概率进度条 → 需要时在历史页回顾、导出或清理记录。
- **验收场景**:主要使用兄弟工程 `data/test` 中的图片,或自备猫狗图片;在 Edge 浏览器中操作。

## 5. 功能需求

### 5.1 页面组成(三个页签,中文文案)

**页签一:单张识别**

1. 标题"猫狗分类识别"。
2. 图片上传控件:支持选择本地图片文件(jpg、jpeg、png、bmp),选中后页面显示图片预览。
3. "开始识别"按钮。
4. 结果显示区:识别类别(猫/狗)+ 置信度百分比 + **猫/狗概率对比进度条**(两条横向进度条分别显示"猫 xx.x%""狗 xx.x%",高概率一侧突出显示)。
5. 简要使用说明文字。

**页签二:批量识别**

1. 两种提交入口,可任选其一:
   - **选择多个图片文件**:一次性多选图片文件(jpg/jpeg/png/bmp);
   - **选择文件夹**:直接选取一个文件夹(Edge/Chrome 支持),浏览器递归收集其中支持的图片后上传。
2. "开始批量识别"按钮;处理期间显示进行中状态。
3. 结果表格:文件名、预测类别、置信度、备注(失败行写明原因)。
4. 汇总统计:总数、成功数、失败数、识别为猫的张数、识别为狗的张数。
5. CSV 下载按钮;CSV 同时自动保存到 `result/`。

**页签三:历史记录**

1. 分页列表:每页固定条数(默认 10 条,可翻页),每条显示缩略图、文件名、预测类别、置信度、识别时间。
2. 操作:删除单条、清空全部、导出历史为 CSV。
3. 历史按识别时间倒序排列。

### 5.2 交互流程

**单张识别**

1. 用户打开页面,进入"单张识别"页签。
2. 选择一张图片,页面显示预览。
3. 点击"开始识别"。
4. 页面显示结果:类别 + 置信度 + 猫/狗概率对比进度条。
5. 该次识别自动写入历史记录。
6. 更换图片可再次识别,多次识别互不干扰。

**批量识别**

1. 切换到"批量识别"页签。
2. 通过"选择多个图片文件"或"选择文件夹"提交图片。
3. 点击"开始批量识别",页面显示进行中。
4. 完成后显示结果表格与汇总统计,并提供 CSV 下载;CSV 已自动保存到 `result/`。
5. 批量中每一张的识别结果均自动写入历史记录。

**历史记录**

1. 切换到"历史记录"页签,查看分页列表。
2. 可删除某一条、清空全部、或导出 CSV(保存到 `result/` 并提供下载)。

### 5.3 识别逻辑(功能层面)

- 输入:单张常见格式图片(jpg/jpeg/png/bmp),统一转为 RGB 三通道。
- 输出:预测类别(猫/狗)、置信度百分比、猫/狗两个类别的概率(softmax 后)。
- 类别映射:索引 `0 → 猫`,`1 → 狗`。
- 置信度 = softmax 后最大类别的概率,保留 1 位小数展示。
- 批量识别逐张复用同一逻辑;单张失败不影响其他图片。

### 5.4 异常与提示

| 场景 | 预期表现 |
| --- | --- |
| 上传非图片文件(如 txt)或图片无法解码 | 中文错误提示,程序不崩溃;批量模式下该张计入失败并写备注,其余继续 |
| 未上传图片就点击识别 | 提示"请先上传图片" |
| 后端未启动/未就绪时打开页面 | 前端给出友好中文提示(如"后端服务未启动,请先运行启动.bat") |
| 权重文件缺失或损坏 | 后端启动时报清晰中文错误,说明缺少 `best_model_opt20.pth` |
| 端口被占用 | 启动脚本/后端给出中文提示,说明 8000 或 5173 端口被占用 |
| 无 CUDA 环境 | 自动使用 CPU 运行(速度较慢但可用) |
| 批量规模过大 | 超过单次上限时给出中文提示(上限见第 12 章建议值) |

## 6. 接口需求(FastAPI)

后端基址:`http://127.0.0.1:8000`;开发时前端经 Vite 代理以 `/api` 前缀访问。所有接口失败时返回 HTTP 4xx/5xx 及 `{"detail": "中文提示"}` 结构。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/classify` | 单张识别。multipart/form-data,字段 `file`(单个图片文件)。 |
| POST | `/api/batch` | 批量识别。multipart/form-data,字段 `files`(多个图片文件)。 |
| GET | `/api/history` | 历史分页查询。参数 `page`(默认 1)、`page_size`(默认 10)。 |
| DELETE | `/api/history/{id}` | 删除单条历史。 |
| DELETE | `/api/history` | 清空全部历史。 |
| GET | `/api/history/export` | 导出历史为 CSV(下载,同时保存 `result/`)。 |
| GET | `/uploads/{filename}` | 获取上传图片(历史页缩略图使用)。 |
| GET | `/docs` | FastAPI 自动生成的接口文档页(附赠,无需开发)。 |

**`POST /api/classify` 成功响应示例**

```json
{
  "id": 42,
  "filename": "cat_001.jpg",
  "predict": "cat",
  "predict_label": "猫",
  "confidence": 0.924,
  "probs": {"cat": 0.924, "dog": 0.076},
  "image_url": "/uploads/cat_001_20260910_103000.jpg",
  "created_at": "2026-09-10 10:30:00"
}
```

**`POST /api/batch` 成功响应示例**

```json
{
  "total": 3,
  "success": 2,
  "failed": 1,
  "cat_count": 1,
  "dog_count": 1,
  "csv_filename": "batch_result_20260910_103000.csv",
  "results": [
    {"filename": "a.jpg", "predict_label": "猫", "confidence": 0.924, "remark": ""},
    {"filename": "b.jpg", "predict_label": "狗", "confidence": 0.887, "remark": ""},
    {"filename": "坏文件.txt", "predict_label": "-", "confidence": null, "remark": "无法读取该图片,请上传 jpg/png/bmp 等图片文件"}
  ]
}
```

**`GET /api/history` 成功响应示例**

```json
{
  "total": 128,
  "page": 1,
  "page_size": 10,
  "items": [
    {
      "id": 42,
      "filename": "cat_001.jpg",
      "predict_label": "猫",
      "confidence": 0.924,
      "probs": {"cat": 0.924, "dog": 0.076},
      "image_url": "/uploads/cat_001_20260910_103000.jpg",
      "created_at": "2026-09-10 10:30:00"
    }
  ]
}
```

接口设计约定:

- 识别成功即写入历史并返回该条记录(前端可直接拿到 `id` 与 `created_at`)。
- 批量接口对每个文件独立处理:坏文件跳过并写备注,不中断整体。
- 删除/清空接口返回 `{"ok": true}` 及删除条数(清空返回 `{"ok": true, "deleted": n}`)。
- 上传文件命名规则:原名 + 时间戳,避免重名覆盖(建议 `原文件名_YYYYmmdd_HHMMSS.扩展名`)。

## 7. 数据需求

### 7.1 SQLite 数据库

- 文件位置:`backend/app.db`(建议),随程序自动创建,无需安装任何数据库软件。
- 表 `classify_history` 字段建议:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER 主键自增 | 记录编号 |
| `filename` | TEXT | 原始文件名 |
| `stored_path` | TEXT | 上传副本在 `uploads/` 下的相对路径 |
| `predict` | TEXT | `cat` / `dog` |
| `prob_cat` | REAL | 猫概率(0~1) |
| `prob_dog` | REAL | 狗概率(0~1) |
| `confidence` | REAL | 最大类概率(0~1) |
| `created_at` | TEXT | 识别时间 `YYYY-MM-DD HH:MM:SS` |

### 7.2 目录约定

| 目录 | 用途 |
| --- | --- |
| `backend/uploads/` | 保存每次上传图片的副本(单张与批量),供历史缩略图展示;程序首次运行自动创建 |
| `backend/result/` | 批量结果 CSV 与历史导出 CSV 的保存位置;程序首次运行自动创建 |
| 根目录 `best_model_opt20.pth` | 权重,只读,后端启动时加载 |

### 7.3 CSV 约定(沿用旧版)

- 编码 `utf-8-sig`,便于 Excel 直接打开无乱码。
- 批量结果列:文件名、预测类别、置信度、备注;失败行预测类别/置信度填"-",备注写原因。
- 批量文件名:`batch_result_YYYYmmdd_HHMMSS.csv`,保存于 `result/`。
- 历史导出列:编号、文件名、预测类别、置信度、识别时间;文件名:`history_YYYYmmdd_HHMMSS.csv`,同样保存于 `result/`。

## 8. 非功能需求

- **界面语言**:简体中文,无乱码,文案风格沿用旧版("猫狗分类识别""开始识别""请先上传图片"等)。
- **易用性**:双击 `启动.bat` 即可使用;全程图形化,无需记忆任何命令(开发时除外)。
- **性能**:单张识别 GPU 环境数秒内返回;CPU 环境可完成但较慢;批量识别逐张处理,页面应显示进行中状态,避免误以为卡死。
- **浏览器兼容**:以 Microsoft Edge(Chromium 内核)为准;文件夹选择功能依赖该内核,Firefox 不支持时自动退化为"仅多选文件"(前端应提示)。
- **可维护性**:后端按 配置/模型加载/预处理/推理/接口/数据库 分层;前端按 页面组件/接口封装 分层;复用现有 `model.py`,不重复定义网络。
- **依赖最小化**:后端在 `pytorch_paoge` 环境仅新增 `fastapi`、`uvicorn`、`python-multipart`(及必要的 `aiofiles` 等);前端依赖由 `package.json` 管理(vue、vite、element-plus、axios)。
- **路径约定**:权重固定为工程根目录 `best_model_opt20.pth`;推理预处理参数必须与 `model_train.py` 完全一致。

## 9. 技术方案要点(供开发实现参考)

### 9.1 技术选型

- 后端:Python + PyTorch + **FastAPI**(ASGI 服务用 **Uvicorn**),端口 8000。
- 前端:**Vue3 + Vite + Element Plus + axios**,开发服务器端口 5173,Vite 配置代理:`/api` → `http://127.0.0.1:8000`。
- 数据库:SQLite(Python 标准库 `sqlite3` 即可,不引入 ORM 也允许;如需更规范可用 SQLAlchemy)。
- 启动:Windows 批处理 `启动.bat`。

### 9.3 模型加载与推理(必须与训练一致)

- 复用 `model.py`:`model = ResNet(residual)`;`model.load_state_dict(torch.load('best_model_opt20.pth', map_location=device))`;`device = 'cuda' if torch.cuda.is_available() else 'cpu'`。
- 预处理:`transforms.Resize((224, 224))` + `transforms.ToTensor()` + `transforms.Normalize(mean=[0.4861, 0.453, 0.4153], std=[0.2628, 0.2555, 0.2583])`;上传图片统一转 RGB。
- 推理:`model.eval()` → `with torch.no_grad():` 前向 → `softmax(logits, dim=1)` → 取双类概率与最大类索引。

### 9.4 环境准备与启动(首次使用需联网)

1. 后端依赖:`conda activate pytorch_paoge`,然后 `pip install fastapi uvicorn python-multipart`。
2. 安装 Node.js(仅首次):官网下载 LTS 安装包,或 PowerShell 执行 `winget install OpenJS.NodeJS.LTS`;安装后新开终端验证 `node -v`、`npm -v`。
3. 前端依赖:在 `frontend/` 目录执行 `npm install`(仅首次)。
4. 日常使用:双击 `启动.bat`,脚本依次启动后端(`uvicorn main:app --port 8000`,于 `backend/` 目录)与前端(`npm run dev`,于 `frontend/` 目录),并自动打开 `http://localhost:5173`。
5. 关闭:关闭两个命令窗口即可(或由脚本提供停止方式)。

## 11. 风险与限制

- **二分类强制输出**:模型只有"猫/狗"两类,对猫狗之外的图片(风景、人像等)仍强制输出猫或狗;本期按用户确认**不提供拒识**(低置信度也不提示)。
- **泛化局限**:模型基于 `data/train` 同分布数据训练,对手机实拍、网络生活照的识别效果可能下降;验收以 `data/test` 及自备猫狗图为准。
- **首次安装需联网**:Node.js 及 pip/npm 依赖首次安装需要网络。
- **权重体积**:`best_model_opt20.pth` 约 45 MB,需与工程在同一目录。
- **浏览器依赖**:文件夹选择依赖 Chromium 内核(Edge/Chrome),Firefox 不支持。
- **批量规模**:建议单次上限 500 张、单张文件 ≤ 10 MB(工程保护性建议值,防止内存与请求过大;超限给出中文提示)。
- **单机自用**:不包含任何公网部署所需的安全配置,请勿直接暴露到公网。
